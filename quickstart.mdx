title: "Quickstart"
description: "Get Audora running locally in under 10 minutes."
---

<Steps>
  <Step title="Install prerequisites">
    Audora requires the following tools before you begin:

    | Tool | Minimum version | Notes |
    |------|----------------|-------|
    | [Bun](https://bun.sh) | 1.3.10 | Package manager and runtime |
    | Node.js | 18 | Required by Next.js |
    | Docker & Docker Compose | Latest | For running PostgreSQL |
    | FFmpeg | Any recent | For media processing |

    <Note>
      Audora uses **Bun** as its package manager. Do not use npm, yarn, or pnpm — the lockfile is a `bun.lock` and workspace resolution depends on Bun's behavior.
    </Note>
  </Step>

  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/NarsiBhati-Dev/audora.git
    cd audora
    ```
  </Step>

  <Step title="Install dependencies">
    Install all workspace dependencies with a single command from the monorepo root:

    ```bash
    bun install
    ```

    This installs dependencies for all three apps (`audora-frontend`, `audora-api`, `audora-signal`) and all shared packages via Turborepo.
  </Step>

  <Step title="Configure environment variables">
    Copy the example environment file and fill in the required values:

    ```bash
    cp .env.example .env
    ```

    Edit `.env` with your values:

    ```bash .env
    # Database
    POSTGRES_PASSWORD=change_me_to_a_secure_password
    DATABASE_URL=postgresql://audora_user:change_me_to_a_secure_password@database:5432/audora

    # Auth — generate with: openssl rand -base64 32
    NEXTAUTH_SECRET=change_me_to_a_random_secret
    NEXTAUTH_URL=http://localhost:3000

    # Google OAuth (optional for local dev — leave blank to skip)
    GOOGLE_CLIENT_ID=
    GOOGLE_CLIENT_SECRET=

    # Frontend (embedded at build time)
    NEXT_PUBLIC_SITE_URL=http://localhost:3000
    NEXT_PUBLIC_HTTP_URL=http://localhost:9000
    NEXT_PUBLIC_SIGNALING_URL=ws://localhost:8000

    # API Server
    PORT=9000
    FRONTEND_URL=http://localhost:3000

    # Kafka (recording pipeline)
    KAFKA_BROKERS=localhost:9092
    KAFKA_TOPIC=recording-chunks

    # Signal Server
    DEBUG=false
    NODE_ENV=development
    ```

    <Warning>
      Never commit `.env` to version control. It is listed in `.gitignore`.
    </Warning>

    Generate a secure `NEXTAUTH_SECRET`:

    ```bash
    openssl rand -base64 32
    ```
  </Step>

  <Step title="Start the database">
    Audora uses PostgreSQL running in Docker. Start it with:

    ```bash
    bun run db:up
    ```

    This runs `docker compose up -d database` and starts a PostgreSQL 16 container on port 5432.
  </Step>

  <Step title="Run database migrations">
    Apply the Prisma migrations and generate the client:

    ```bash
    bun run db:deploy
    ```

    This runs `prisma migrate deploy` inside the `packages/database` workspace, creating all tables (User, Studio, Project, Track, Recording).
  </Step>

  <Step title="Start all services">
    Start all three services in development mode via Turborepo:

    ```bash
    bun run dev
    ```

    Once running, open your browser to:

    | Service | URL | Description |
    |---------|-----|-------------|
    | Frontend | http://localhost:3000 | Next.js app |
    | API | http://localhost:9000 | Express REST API |
    | Signal | ws://localhost:8000 | WebSocket signaling |
    | Signal health | http://localhost:8001/health | Health check endpoint |
  </Step>
</Steps>

## Alternative: full Docker Compose

If you prefer to run everything in Docker (including the app services), use:

```bash
bun run infra:up
```

This runs `docker compose up -d` and starts all four services (frontend, backend, signal, and database) using the production Dockerfiles. All service ports are the same as above.

<Tip>
  The Docker Compose setup uses health checks on every service so dependent services wait for their dependencies to be healthy before starting.
</Tip>

## Starting individual services

You can start services individually for faster iteration:

<CodeGroup>
```bash Frontend only
bun run start:frontend
```

```bash API only
bun run start:api
```

```bash Signal server only
bun run start:signal
```
</CodeGroup>
