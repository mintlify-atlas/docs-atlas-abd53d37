Audora is a **monorepo** managed with [Turborepo](https://turborepo.com). All applications and shared packages live in the same repository, which lets them share code, configuration, and build caches without publishing to a package registry.

```text
audora/
├── apps/
│   ├── audora-frontend/       # Next.js UI
│   ├── audora-api/            # Express REST API
│   └── audora-signal/         # WebSocket signalling server
├── packages/
│   ├── database/              # Prisma schema and database services
│   ├── types/                 # Shared TypeScript types and Zod schemas
│   ├── typescript-config/     # Shared tsconfig bases
│   ├── eslint-config/         # Shared ESLint configurations
│   └── tailwind-css/          # Shared Tailwind CSS configuration
├── docker/                    # Production Dockerfiles
├── .github/workflows/         # GitHub Actions CI/CD pipelines
├── turbo.json                 # Turborepo pipeline configuration
├── docker-compose.yml         # Full-stack Docker Compose
└── package.json               # Root workspace configuration
```

## Package naming convention

All internal packages follow the `@audora/*` scoped naming convention:

```
@audora/database
@audora/types
@audora/typescript-config
@audora/eslint-config
```

In any app's `package.json`, internal packages are referenced using the workspace wildcard version:

```json
{
  "dependencies": {
    "@audora/database": "*",
    "@audora/types": "*"
  },
  "devDependencies": {
    "@audora/eslint-config": "*",
    "@audora/typescript-config": "*"
  }
}
```

Bun workspaces resolve `"*"` to the local package on disk — no registry publishing required.

## Turborepo pipeline

The `turbo.json` at the repository root defines the **task pipeline** — the dependency graph that Turborepo uses to order and cache work across packages.

```json
{
  "$schema": "https://turborepo.com/schema.json",
  "ui": "tui",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".next/**", "!.next/cache/**"]
    },
    "lint": {
      "dependsOn": ["^lint"]
    },
    "check-types": {
      "dependsOn": ["^check-types"]
    },
    "dev": {
      "cache": false,
      "persistent": true
    },
    "start:api": {
      "dependsOn": ["^db:deploy"],
      "cache": false,
      "persistent": true
    },
    "start:signal": {
      "dependsOn": ["^db:deploy"],
      "cache": false,
      "persistent": true
    }
  }
}
```

### Pipeline tasks

| Task | `dependsOn` | Cached | Description |
|---|---|---|---|
| `build` | `^build` | Yes | Builds all packages before apps that depend on them |
| `lint` | `^lint` | Yes | Lints packages in dependency order |
| `check-types` | `^check-types` | Yes | Type-checks in dependency order |
| `dev` | — | No | Starts all dev servers concurrently (persistent) |
| `start:frontend` | `build` | Yes | Builds then starts the Next.js server |
| `start:api` | `^db:deploy` | No | Runs migrations before starting the API |
| `start:signal` | `^db:deploy` | No | Runs migrations before starting the signal server |

<Tip>
  The `^` prefix in `dependsOn` means "run the same task in all upstream dependencies first". For example, `"dependsOn": ["^build"]` ensures every package the app imports is built before the app itself.
</Tip>

## Adding a new package

<Steps>
  <Step title="Create the package directory">
    ```bash
    mkdir packages/my-package
    ```
  </Step>

  <Step title="Add a package.json">
    Follow the `@audora/*` naming convention:

    ```json
    {
      "name": "@audora/my-package",
      "type": "module",
      "private": true,
      "exports": {
        ".": "./index.ts"
      },
      "devDependencies": {
        "@audora/typescript-config": "*",
        "typescript": "^5.9.3"
      }
    }
    ```
  </Step>

  <Step title="Add a tsconfig.json">
    Extend from the shared config:

    ```json
    {
      "extends": "@audora/typescript-config/base.json",
      "include": ["."],
      "exclude": ["node_modules"]
    }
    ```
  </Step>

  <Step title="Add the package as a dependency">
    In any app or package that needs it, add to `package.json`:

    ```json
    {
      "dependencies": {
        "@audora/my-package": "*"
      }
    }
    ```

    Then run `bun install` from the repository root to link the workspace.
  </Step>
</Steps>

## Adding a new app

<Steps>
  <Step title="Create the app directory">
    ```bash
    mkdir apps/my-app
    ```
  </Step>

  <Step title="Add a package.json">
    Apps do not need to follow the `@audora/*` scope — use a plain name:

    ```json
    {
      "name": "my-app",
      "type": "module",
      "private": true,
      "scripts": {
        "dev": "bun run src/index.ts",
        "build": "bun build src/index.ts --outdir dist",
        "lint": "eslint . --max-warnings 0",
        "check-types": "tsc --noEmit --pretty"
      }
    }
    ```
  </Step>

  <Step title="Run bun install">
    ```bash
    bun install
    ```

    Bun automatically picks up the new workspace member from the root `workspaces` glob (`apps/*`).
  </Step>
</Steps>
